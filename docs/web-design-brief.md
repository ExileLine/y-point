# Y-Point 前端设计简报（开发准备）

参考来源：TencentCloud/Octop `dashboard/`，检视提交 `890111b7879665840414ca28ab168b05b0db0921`（2026-10-29）。只分析布局、交互和组件组合，不复用源码、文案、图标或品牌素材。Y-Point 的功能范围以本仓库 `README.md`、`y-point-server-todo.md` 和实际 OpenAPI 为准。

## 布局骨架

- Octop 桌面端以左侧分组导航和右侧工作区为主，Chat 再加会话历史栏；全局顶部 Header 主要用于移动端，普通页面使用固定页标题、可选副标题与右侧操作区。Chat 采用全高工作台，消息区独立滚动，输入区固定在底部。
- 普通管理页的标题和操作留在视野内，筛选、Tab 与列表形成紧凑的扫描路径。宽表格在表格容器内横向滚动，避免整页溢出。移动端收起全局导航，会话栏通过抽屉进入，页面工具栏换行或收纳次要操作。
- Y-Point 首期导航建议：对话、Agent、管理（用户、供应商、模型、审计）、个人设置。只展示有服务端能力和权限的入口。会话属于选定 Agent 的工作台层级；独立文本 Run 是否提供单独入口待定。

## 页面信息层级

| Octop 页面 | 可借鉴的区块顺序 | Y-Point 首期映射 |
| --- | --- | --- |
| Chat | 会话入口与标题 → 历史/运行内容 → 附件及过程状态 → 底部输入；空白会话、恢复中、失败分开呈现。 | Agent/会话选择 → 消息列表与 Run 状态 → 附件/产物 → 输入与取消/审批。最终消息以会话 `messages` 为准。 |
| Experts | 页面标题 → 分类 Tab → 数量/筛选/搜索/视图切换/新增 → 卡片或表格 → 侧边编辑。 | “我的 Agent”和“共享给我”分视图；拥有者可编辑自己的 Agent，共享视图只显示安全摘要及进入会话操作。 |
| Connectors | 页面标题 → 已启用/目录分类 → 数量和刷新 → 实例列表或空态 → 配置 Drawer。 | M5 后再映射 MCP；首期不出现可点击连接器入口。 |
| Cron | 页面标题 → 列表统计与视图切换 → 行操作/详情/创建 Drawer；首屏加载和刷新中分别反馈。 | 当前服务端无 Cron 业务契约，作为列表密度和状态处理参考，不纳入首期导航。 |
| Settings | 分类 Tab → 当前配置概览 → 按主题分组的表单/列表 → 增删改弹层和局部错误。 | 首期映射个人资料、管理员供应商/模型；其他配置按服务端里程碑开放。 |

## 视觉语言

- Octop 的浅色基线是白色工作面、偏冷灰页面底色、深灰正文和更浅的辅助文字；默认强调色偏玫红。其主题变量还支持不同品牌色和暗色模式。Y-Point 不采用 Octop 的色值。
- 常用字号落在 12～14px 的密集信息区，普通页标题约 20px；页内分组依赖标题、间距和分隔线，不用处处套卡片。桌面页面外边距较宽，内容区留出约 24px 的操作空间；移动端缩到约 12px。卡片和浮层使用轻边框、低强度阴影。
- Y-Point 已从 `docs/logos.png` 第三排第一个方案裁出深蓝 / 亮蓝 Y 与橙色圆点图标、字标，用于 W0 布局骨架。当前源图仍是候选位图；正式发布前需确认原始资源与缩放质量。首期默认浅色；暗色模式需求待定，若需要再设计完整的语义色映射。

## 组件组合

- Octop 用 Ant Design `ConfigProvider` 统一基础组件主题；`Tabs`、`Segmented`、`Input`、`Button`、`Form`、`Select`、`Switch`、`Drawer`、`Modal`、`Spin`、`Empty`、`Alert`、`Tooltip` 等高频出现。导航与 Chat 工作台有较多定制实现。Y-Point 的全局骨架按参考标准使用 Ant Design `Layout/Menu`。
- 资源列表：页标题 + 工具栏 + `Tabs`/筛选 + `Table` 或简洁卡片 + `Pagination`；窄屏可切为逐项列表。配置：`Form` 分组，少量字段用 `Drawer` 编辑，危险操作用 `Popconfirm`/`Modal` 确认。
- Chat：Ant Design 负责按钮、输入、上传选择、状态反馈和审批弹层；消息流与底部输入的布局可定制，但颜色、字号、间距、圆角和阴影全部取自语义 tokens。

## 值得借鉴的交互

1. 首次加载与后台刷新分开：已有列表保持可读，仅在局部显示刷新中。
2. 无资源与筛选无结果使用不同空态；主操作直接放在真正的空态里。
3. 搜索和筛选紧贴列表标题与数量，避免用户忘记当前过滤条件。
4. 卡片/表格切换保留用户偏好，但只在信息量需要时提供双视图。
5. 编辑用侧边抽屉维持列表上下文；提交中禁用重复操作并反馈结果。
6. 页面权限和可见 Tab 随当前身份变化；无权限直达地址有明确反馈。
7. Chat 切换会话时保持工作台骨架，历史加载中不闪回欢迎空态。
8. 移动端把全局导航和会话栏做成可独立打开的层，输入区保持可用。

## 品牌与边界

借鉴的是导航密度、页标题/工具栏/内容的顺序、局部滚动、状态分层和组件选择。Y-Point 必须使用自己的名称、标识、蓝橙品牌色、业务文案、Lucide 图标与真实数据；不使用 Octop 吉祥物、头像、插画、预设资源和其 Chat 功能入口。服务端尚未交付的 Skill/MCP、知识库、记忆、Cron、插件、ACP、问数不做可点击空壳。
