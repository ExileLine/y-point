# Agent 会话与文本对话交接

会话入口位于 Agent 卡片、表格与详情，路由为 `/agents/{agent_id}/sessions`。桌面展示会话栏和消息区，手机在列表与当前会话间切换。所有者与被共享用户分别拥有自己的会话；共享用户读取的是 Agent 安全摘要。

会话页的外层留白为桌面 8px、手机 4px，面板使用侧栏之外的完整可用宽度。Agent 名称和返回入口位于左侧会话栏，手机进入对话后在当前会话标题区显示 Agent 名称，不另占顶部整行。模型选择、「审批选项」按钮与「附件」上传入口共用工具行。模型框采用紧凑宽度（最大 240px），长名称省略显示，提示中保留完整名称、供应商与能力信息，供应商副标题仅在下拉目录中展示。附件入口保留点击和拖拽上传，文件列表按需展开。输入框始终保留至少三行编辑空间，随内容增高至六行；整个输入区最多占面板高度的 45%。附加多个文件时，附件区域内部滚动，消息输入框和发送按钮保持可见；历史消息区保留独立滚动、阅读位置保持与「回到最新消息」。问答使用完整可用宽度，不再限制在居中的 760px 栏内；用户提问靠右显示，Agent 的历史回复、生成中回复与未完成回复从左侧展开，消息区左右留白为桌面 16px、手机 8px。运行状态标签、运行审批与工具结果区均对齐助手正文的起始位置。附件数量和大小限制可通过上传入口提示查看，手机与桌面使用相同上传校验。

消息输入框使用 Enter 发送，Shift+Enter 换行；中文输入法组合输入与确认候选词、长按回车、空白内容及附件未就绪时不触发提交。键盘与发送按钮复用同一发送流程，同一会话正在提交时由即时引用锁阻止重复请求；失败后释放锁，原有同键重试继续有效。

| 操作 | 接口 | 前端处理 |
| --- | --- | --- |
| Agent 资料 | `GET /api/v1/agents/{id}`，共享时回退 `GET /api/v1/agents/shared/{id}` | 共享页不读取或显示系统指令；404 清除失效会话内容。 |
| 会话列表 | `GET /api/v1/agents/{id}/sessions?page=&page_size=20&archived=&search=` | 标题搜索、归档筛选和分页均由服务端执行。 |
| 新建与详情 | `POST /api/v1/agents/{id}/sessions`、`GET /api/v1/agents/{id}/sessions/{session_id}` | 新建后进入独立会话；刷新路由时重取会话。 |
| 重命名与归档 | `PUT /api/v1/agents/{id}/sessions/{session_id}` | 提交 `expected_version`；409 展示错误并刷新列表。归档后禁止发送。 |
| 删除 | `DELETE /api/v1/agents/{id}/sessions/{session_id}` | 确认后删除；运行中服务端拒绝并保留会话。 |
| 消息与 Run 恢复 | `GET /api/v1/agents/{agent_id}/ag-ui/threads/{session_id}`、`GET /api/v1/agents/{agent_id}/sessions/{session_id}/runs` | 协议历史提供正文，messageDetails 提供文件与交付信息；页面刷新后找回仍在运行的 Run。 |
| 文本提交与状态 | `POST /api/v1/agents/{agent_id}/ag-ui`、`GET /api/v1/runs/{run_id}`、`POST /api/v1/runs/{run_id}/cancel` | 每轮生成新消息 ID 与协议 runId，携带 `forwardedProps.expected_session_version` 仅提交新用户消息；发送前不请求完整历史。无法确认提交结果时保留原请求及身份供明确重试；版本冲突保留草稿、刷新状态，由用户重新发送。标准 POST 返回流供当前页面直接消费；业务 Run 详情用于绑定运行资源及连接异常时核实状态。 |
| 运行中回答 | AG-UI POST SSE；恢复使用 `GET /api/v1/runs/{run_id}/ag-ui/snapshot` 与 `GET /api/v1/runs/{run_id}/stream?after=<wire_sequence>` | 首次发送不重复建立 GET 订阅；刷新或断线时冻结分页上界、追平快照、签发票据并续接观察，统一按协议线游标去重。详见 [AG-UI](ag-ui.md)。 |
| 产物与附件下载 | `GET /api/v1/artifacts/{artifact_id}/download` | 从消息的 `attachments` / `artifacts` 获取 ID，逐次携带 Bearer；401 刷新后重试一次，失败回到登录。按服务端 `Content-Disposition` 文件名及原始 MIME/字节保存，HTML 仅下载；403/404 与网络失败显示提示，可重试。 |
| 调用名称与状态 | AG-UI `ACTIVITY_SNAPSHOT` 和消息事件 | 实时与历史使用同一 reducer，区分 Skill 阶段及工具执行结果；不按每个工具事件重读 `/calls`，未知外部结果显示“结果未确认”。 |

会话支持文本发送、历史查看、附件上传与产物下载及审批。最终正文从公开协议历史读取，文件等业务元数据按协议消息 ID 关联；文件操作时重新授权。对话提交与公开历史的入口边界见[AG-UI 接口兼容边界](ag-ui.md#接口兼容边界)。

## 对话体验与消息格式

发送成功、产物事件、手动刷新和 Run 终态只触发后台同步，已有消息与会话目录保持挂载。首次进入且没有历史数据时才显示骨架屏。

消息区使用固定可视高度与独立滚动。初次进入和主动发送跟随最新内容；在底部时按内容增长跟随，向上阅读后保留位置，显示「回到最新消息」。手动刷新保持阅读位置；流式预览到最终消息之间持续显示同一轮回复，最终正文仍以服务端 messages 为准。

用户消息在右侧，助手消息在左侧。助手正文使用 Markdown/GFM：标题、强调、列表、任务列表、引用、分隔线、链接、表格、行内代码及语言代码块；代码块显示语言与复制按钮，整条消息可复制原文。完整 HTML 文档与有效 JSON 自动显示为源码块；HTML 不执行，未声明语言和未知语言回退为可读源码。表格和代码在自身区域横向滚动；外链使用新窗口和 noopener/noreferrer，远程 Markdown 图片展示为可点击链接。

流式文本仍按 SSE sequence 去重与快照追平，呈现层用 requestAnimationFrame 分帧平滑追加，按字素切分避免拆断 Emoji 和组合字符。积压时自适应追赶，完成后使用服务端最终正文；流式阶段不反复执行代码高亮，最终正文再高亮。系统偏好减少动态效果时直接显示已收到的文本。

## 消息操作栏

助手历史回复提供复制、重新生成、喜欢、不喜欢和分享五个纯图标按钮，悬停或键盘聚焦显示名称；用户消息提供复制，生成中预览与完成回复使用同一组五个图标按钮。代码复制同样仅显示图标。复制功能已实现，其余入口点击显示「功能待接入」，待后端契约交付后补齐，不记录虚假的反馈或分享状态。

## 产物与附件下载

助手消息 `artifacts` 与用户消息 `attachments` 使用 `MessageFiles` 文件卡片，展示文件名、来源、提供给模型的状态和可用性；下载按钮沿用纯图标、悬停/聚焦提示。不可用文件保留在历史中并禁止下载，下载中显示加载状态、防止重复请求，失败后恢复操作。只有服务端已发布到消息的文件才出现下载入口；正文中的文件名和模型声称生成完成不代表文件已发布。

点击后由 `downloadArtifact` 调用服务端授权接口，文件保留原始字节、MIME 与 UTF-8 文件名，不把文本或 JSON 重新序列化；缺少有效文件名时回退消息中的文件名。服务端仍逐次校验文件所有权及存储可用性；前端可用状态仅是展示依据。下载不切换页面、不重新提交 Run，也不执行 HTML。运行内 `y-point.artifact.available` 事件触发历史消息重读；异步回答 TXT 就绪通过 `y-point.resource` 通知。文件卡片按支持格式提供授权预览与下载；原生会话默认不请求回答 TXT 导出。

对话支持上传 `.pptx` 并选择「供模型读取」，提取页码、文字、表格及演讲者备注；生成的 PPTX 使用相同文件卡片提供按页内容预览与原件下载。图片、图表、动画和原始版式以 PowerPoint 原件为准，隐藏内容不进入上下文或预览，详见 [PowerPoint 演示文稿](artifacts.md#对话中的-powerpoint-演示文稿)。

## 调用名称与状态

`RunActivity` 在助手正文上方展示按时间交错的公开思考、中间说明、工具及 Skill 活动。工具卡片保留名称、状态、耗时和受控失败原因，颜色之外同时提供文字或图标；名称按内容换行，每次调用按稳定关联 ID 独立展示。用户 Tool 使用调用时记录的显示名称；知识检索目标按当前授权过滤，旧工具名称不会因后续改名或删除而被改写。

新提交直接消费 AG-UI POST 流，历史过程从 AG-UI 快照恢复；断线时先追平冻结上界的快照，再续接观察流，实时和历史使用同一 reducer。切换会话会取消旧观察请求。最终回答与文件单独呈现，没有最终助手消息的失败轮次保留过程及已公开的未完成正文；每次调用保留独立结果，不把整轮失败套用到所有调用，也不把无命中的成功检索标成失败。

## 工具审批

脚本 Tool 使用「调用前需要审批」开关，默认关闭；MCP Tool 使用连接默认与工具覆盖的 `always/writes/never`，再叠加本轮主动要求、共享使用与部署限制。当前审批设置在新 Run 提交时固定，无需仅为审批调整重新保存 Agent；执行版本仍按原绑定固定。具体规则见[审批声明与可调用状态](tools.md#mcp-审批声明与可调用状态)。

进入 `waiting_for_approval` 后，页面自动读取 `GET /api/v1/runs/{run_id}/approval`，展示工具名、脱敏参数摘要和授权文件名；`expires_at=null` 时提示「等待你的决定，不设审批时限」，不显示截止日期，刷新后也能恢复。用户可批准、拒绝本次并继续或停止整个任务；多项审批支持逐项决定，任一停止会终止整批未执行项。旧客户端 `reject` 保留取消整轮的语义。

决定通过新的协议 runId 向 `POST /api/v1/agents/{agent_id}/ag-ui` 提交 `resume`，使用当前 `interruptId` 与明确的 `decision`；相同恢复请求重试复用原身份和完整输入。`approve` 可在服务端 `allowed_scopes` 允许时选择 `once/tool/all`；扩大范围只适用于明确批准全部当前动作。查询失败时暂停决定并提供重试，提交期间锁定操作，冲突、取消或过期由服务端拒绝。

点击输入区「审批选项」后，在按钮上方弹出跟随屏幕边界调整位置的小面板，提供本轮 MCP 审批开关，以及会话放行策略查看、刷新和撤销。面板不占用对话与输入区高度，可通过关闭按钮、点击外部或 Esc 收起；键盘关闭后焦点返回触发按钮，切换会话会关闭旧会话面板。策略来自 `GET /api/v1/agents/{agent_id}/sessions/{session_id}/approval-policy`，撤销使用同路径 DELETE 并携带独立的 `expected_version`，可指定 `tool_id`。放行只覆盖确认时的固定工具版本集合，切换会话不继承；部署、Run 与共享使用的强制约束不能由会话放行覆盖。详见[对话内放行与撤销](tools.md#对话内放行与撤销)。

协议活动和项目观察扩展共同更新状态，在审批中断、恢复与下一次审批时同步面板。页面不回显原始参数或凭据，撤销不撤回已经执行的操作。
