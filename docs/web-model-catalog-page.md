# 模型与供应商接口交接

管理员页面位于 `/models`。标签顺序为「供应商 → 模型」，默认打开供应商；手机端使用逐项列表。创建连接按 `GET /api/v1/providers/kinds` 的字段清单显示表单。编辑时仅提交变更字段，密钥与自定义请求头留空即保留原值，界面只展示“已配置”。

新建连接的文本、密钥、地址、超时和备注等字段提供中文输入提示与示例；接口地址优先显示该供应商类型建议的地址。

「录入模型」选择连接后自动调用 `GET /api/v1/providers/{id}/available-models`，在可搜索的候选框中显示模型名称及供应商模型 ID。选择候选会带入准确 ID，并在未自定义名称时带入显示名称；已录入候选不可重复选择。加载期间禁用模型 ID 与保存，失败或空列表提供重新发现与手动填写入口；切换连接清除旧 ID、候选及自动名称，保留用户自定义名称，并取消旧请求、忽略过期响应。新录入表单默认选中六项对话声明能力；嵌入模型需手动选择「嵌入」，可以取消不支持的对话能力。声明后仍需逐项验证；编辑现有模型保留其配置。

| 操作 | 接口 | 状态与边界 |
| --- | --- | --- |
| 连接列表与配置 | `GET/POST /api/v1/providers`、`PUT/DELETE /api/v1/providers/{id}` | 管理员权限；409 显示活跃 Agent 引用或关联模型冲突。 |
| 连接探测与发现 | `POST /api/v1/providers/{id}/test`、`GET /api/v1/providers/{id}/available-models` | 展示可用性、耗时和脱敏故障类型；发现失败或无候选时可手动录入。 |
| 模型目录与配置 | `GET/POST /api/v1/models`、`PUT/DELETE /api/v1/models/{id}`、`POST /api/v1/models/import` | 管理员权限；候选导入声明文本能力，仍须实际验证。价格为每百万 Token 的输入/输出价格。 |
| 模型探测 | `POST /api/v1/models/{id}/test`、`POST /api/v1/models/{id}/capabilities/test` | 测试可能产生上游费用；已验证能力与声明能力分开显示。 |
| 嵌入验证 | `POST /api/v1/models/{id}/embedding-test` | 「验证能力 → 验证嵌入」调用独立接口，展示实际维度；成功刷新能力标签，纯嵌入模型显示「可用于知识库」。失败不会标记已验证。 |
| 全局默认 | `POST /api/v1/models/{id}/default` | 页面仅对启用、已验证文本能力且未确认访问故障的模型提供此操作。 |
| Agent 模型选项 | `GET /api/v1/models/available` | 登录用户可读，返回 ID、名称、窗口及 `selectable`、`notice`；已确认访问故障的文本模型保留在目录中，禁用选择并说明原因，停用或窗口过小的模型不提供选项。 |

历史能力验证与当前访问状态分别保存。文本测试、能力测试或实际对话确认供应商返回 404、401、403 时，模型显示「暂不可用」及部署、接口或授权修复指引；Agent 新建和会话发送同步阻断。连接发现成功或模型出现在供应商列表中，不代表实际文本调用成功。短暂网络故障、429 和 5xx 不据此持续阻断模型。

管理员修复供应商模型部署、对外模型 ID、接口地址或 API Key 授权后，点击「测试文本调用」；成功会解除访问阻断，模型仍须满足对应能力要求。已有会话点击「刷新模型状态」后可以继续，无需重建 Agent 或会话。

知识库的嵌入模型列表仅展示启用且已声明或已验证 `embedding` 能力的模型。供应商候选导入默认声明 `text`，模型名称包含 embedding 不会自动改变能力：请在模型编辑页添加「嵌入」，保存后可在模型目录或知识库编辑页完成独立嵌入验证，再创建混合检索知识库。验证会调用实际模型接口，可能产生费用；文本验证不能替代嵌入验证。已有知识库创建窗口需要关闭后重新打开以加载最新模型目录。

## 标签配色

状态采用浅色背景、鲜明边框和清晰文字：启用/可用为绿，待验证为橙黄，失败为红，处理中为蓝。模型能力按类型区分：文本蓝、流式青、工具紫、结构化输出绿、视觉粉紫、推理摘要橙；有勾表示已验证，虚线边框表示待验证，悬停可读验证说明。桌面与手机使用相同标签，不根据鲜亮配色推断模型已通过验证。
