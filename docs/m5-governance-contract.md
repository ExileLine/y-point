# M5.1 治理与验收契约

本文约定 Tool/MCP/Skill/脚本依赖的基础治理及当前兼容边界。

## 版本、凭据与授权

Tool 定义仍以不可变版本关联 Agent/Run，代码、Schema、依赖、连接和凭据不会被后续编辑静默替换。启停、私有化、删除、凭据撤销和共享授权是调用时持续复核的规则；快照不能绕过撤权。

新建 MCP Tool 复用共享连接，凭据通过 `PUT /api/v1/mcp-connections/{id}` 管理；更新提交完整配置及 `expected_version`。Tool 固定发布时的连接配置和版本，连接普通更新不修改旧快照。

| 连接操作 | API 规则 | 旧快照与运行中的行为 |
| --- | --- | --- |
| 保留凭据 | 同传输下省略或留空 HTTP `bearer_token`、stdio `env` | 保留已保存凭据；更换 stdio 配置时仍校验环境变量白名单。 |
| 替换/轮换 | 提供非空 `bearer_token` 或非空 `env`；stdio 凭据对象整体替换 | 递增连接版本，撤销历史凭据版本并取消相关活动运行；采用新凭据需重新发布 Tool 并更新 Agent 关联。 |
| 清除凭据 | `clear_credentials=true`，与新凭据互斥 | 清除凭据并撤销历史版本；后续发布和调用按当前授权重新验证。 |
| 停用或删除 | PUT `enabled=false` 或 DELETE 连接 | 阻断旧快照的新调用并请求取消相关活动运行，保留历史审计。 |
| 关闭凭据共享 | PUT `share_credentials=false` | 其他用户使用该连接凭据的旧快照失效，相关活动运行请求取消。 |

直接保存 URL 的旧 HTTP Tool 继续使用 `mcp_bearer_token`、`clear_mcp_credentials` 维护凭据；绑定共享连接后在连接管理中操作。`POST /api/v1/tools/{id}/credentials/revoke` 仍可撤销指定 MCP Tool 的历史凭据并禁用该 Tool，其作用范围不替代共享连接的整体撤权。

排队与待审批运行直接结束；运行中任务进入 `cancel_requested`，正式 worker 监视取消并停止模型/工具。已经发出的上游操作无法撤回，外部结果不明时须核对，不能以本地取消成功证明远端无副作用。密文保留在旧版本用于历史核对，响应、事件和日志不回传明文密钥。

## MCP 接收与发现预算

以下网络预算适用于 Streamable HTTP。受控 stdio 的容器配置、stdout/stderr 预算和回收规则见 [Tool 指南](tools.md#stdio-受控运行)；两种传输共用发现数量、调用结果及权限治理。

- 每条连接包含初始化、发现、调用和 SSE 的累计接收预算，默认 1 MiB；在字节交给 SDK 前执行。超限或非法声明长度关闭原始响应。
- 请求使用 `Accept-Encoding: identity`，拒绝上游压缩编码，避免解压绕过预算；支持 HTTP/HTTPS、公网、内网、回环及保留地址与自定义端口；按本次 DNS 解析结果固定目标 IP、原协议和端口，HTTPS 保留 TLS 原域名，拒绝全部重定向。
- 发现覆盖分页，默认最多 128 个工具、总结果 256 KiB；单项名称 128 B、描述 4 KiB、Schema 16 KiB。重复名称、循环游标和过多空页均拒绝。
- 发现总时限 15 秒；正式调用由 Agent 单次工具时限、`MCP_CALL_TIMEOUT_SECONDS` 与连接时限共同约束；对话不设置整轮总倒计时。调用结果仍执行解析后的 64 KiB 限制。

## 外部写入恢复

执行许可与恢复能力分别判断。普通写操作可采用 `recovery_policy=manual`，按有效策略获得本次授权和审批后执行一次，不要求远端提供不存在的幂等字段。没有远端只读声明表示缺少证据，按可能写入治理；所有者可在私有工具中附理由确认只读，保存版本绑定证据，相关执行定义变化后重新确认。显式非只读提示不能人工降级，共享使用者不自动信任人工或历史只读声明。

MCP 审批由连接默认、工具覆盖、使用者收紧和部署限制共同确定，默认审批写入和未知操作；普通非幂等写不能设置为免审批。`always` 对已验收幂等写同样生效。模式、快照和兼容布尔字段见 [MCP 审批、声明与可调用状态](tools.md#mcp-审批声明与可调用状态)。

声明幂等恢复时保留逐版本验收：

1. 版本声明 `effect=write`、`recovery_policy=idempotent` 和顶层字符串 `idempotency_key_field`，字段须存在于远端 Schema。
2. 管理员验证重复提交的副作用及响应丢失后的核对方式，通过 `/tools/{id}/write-contract/verify` 提交版本和证据引用；数据库保存引用摘要，审计记录验收动作。新版本重新验收，旧证据不自动继承。
3. 模型工具 Schema 隐藏幂等键，平台使用正式调用 ID 注入；验收不替代业务授权，也不覆盖明确的审批要求。
4. 成功保存 `completed`。平台可证明业务调用尚未发送的失败保存 `failed`；发送后超时、断线、取消或进程失联且结果不能确认时保存 `unknown`。结束 Run 遗留的 `running` 调用继续保守转为未知。
5. 相同调用 ID 禁止再次发送；同一 Run、Tool 和相同参数已有未知记录时，也禁止自动换调用 ID 补做。平台不承诺远端恰好执行一次，取消不等于回滚。

历史普通写定义仍保留，后续执行要求审批；历史声明幂等但未验收的版本仍阻断。参数错误与只读工具错误的纠错能力保持既有边界，不能将未知写结果作为可重试参数错误反馈给模型。

## 跨进程并发

`yp_tool_execution_gate` 的固定行写锁串行化名额判定，`yp_tool_execution_lease` 持久化占用。SQLite 使用写事务，PostgreSQL/MySQL 使用行锁；计数读取使用当前锁定读，避免 MySQL 可重复读快照造成超卖。表间不设置数据库外键。

| 类别 | 默认上限 | 满额行为 |
| --- | --- | --- |
| 工具调用、MCP 发现、脚本试运行 | 全局 16，用户 4，Run 2 | API 返回 429；运行返回脱敏 `tool_capacity_exceeded`，不发送工具请求 |
| 依赖准备 | 全局 2，用户 1 | 保留 `pending`，后续轮询继续领取 |

审批暂停不占执行名额。调用成功、失败和取消均释放；宿主强杀时保留至“操作时限 + 30 秒”到期后再领取。限制是单个共享业务数据库内的全局值，所有进程须使用一致配置与时钟。依赖任务自己的版本租约继续负责互斥领取和准备结果提交。

## 清理、容量及部署范围

新建容器、代理与临时网络带 `y-point.managed`、共享目录作用域摘要和到期时间；临时目录和新缓存带 `.yp-resource.json`；缓存发布前写入并纳入完整性摘要，发布后数据库引用尚未提交时强杀产生的孤立缓存也可按标记回收。正常退出沿用即时清理，常驻 worker 另每 60 秒核对，过期资源等待 300 秒宽限后回收。手动执行：

```bash
uv run python -m app.cli.reconcile_tool_resources
```

核对只触及本部署标签及标记，先删除过期容器/代理，再删除网络。仍有有效资源租约时保守保留临时目录；有任何历史 Tool 版本引用的环境目录不删除，包括逻辑删除的版本。未标记的历史 Docker 资源、目录及缓存自动回收不在本命令的删除范围内。

构建前在共享文件锁下预留 512 MiB，并检查现有缓存、在建预留和文件系统余量。默认应用预算 8 GiB、最低余量 1 GiB；占用/预留到预算 80% 或余量不足时输出告警，容量不足的新准备任务返回脱敏失败。运行中继续执行单文件及构建目录限制。

这些措施是应用预算、准入和故障回收，**不是文件系统硬磁盘配额**。需要硬隔离时须在目标主机提供专用卷/文件系统配额并实际验证；磁盘块、inode、Docker 数据目录和日志也须纳入部署预算。API 与 Worker 需要使用一致的基础镜像和共享环境目录；跨主机分发、远端卷锁语义和目标平台 wheel 需要对应环境验证。

## 迁移与兼容

历史读取版本沿用 `safe` 策略；未完成恢复契约核对的历史写版本保持 `manual`，不自动启用恢复，既有内容摘要不重写。

目标实例升级前备份业务库和检查点；执行 `alembic upgrade head`、`alembic check`，再重启 API/worker。回退会移除治理字段及短期租约，生产回退前必须停止领取新任务并核对进行中的外部调用，不能把回退当作撤销远端副作用。

## 验证方法

通用环境准备、隔离测试与结构检查见[数据库迁移与测试](testing.md)。治理验证需分别覆盖权限、外部写恢复、并发容量、资源清理及目标存储，不能以声明字段代替真实外部写入契约核对。

MCP Run 会话不占审批期间的业务调用名额，但继续占用独立的协议会话资源配额。拥有者路由、心跳、HTTP 加密失主回收凭单、stdio 孤儿截止与尽力取消见 [会话生命周期](tools.md#run-内-mcp-会话与跨审批恢复)；业务租约释放不能解释为远端资源已回收。

### MCP 批次 E：业务成功与结果交付分开记录

只有完整成功响应才能产生“成功但交付受限”的结果引用；远端 `isError` 或传输中断不满足该条件，发送后的写结果仍按未知治理。正式 Worker 先持久化调用成功证据，再尝试大结果留存；文件交付超时不会覆盖已完成的调用审计，整轮仍可以按工具时限终止。已发送写操作不因结果过大、文件配额或读取失败自动重做。

结果只归运行所有者，Agent/连接共享不转授产物；模型读取仅当前 Run，用户私有下载仍逐次授权。保存完整脱敏的单次响应，固定哈希、来源、范围与期限；没有远端全量证据时不将预览当作全量。Run 的上下文估算是脱敏诊断，不是计费数据；静态集合与调用授权过滤共用，尚未启用动态工具搜索。详见 [结果契约](tools.md#mcp-大结果预览保存与分段读取)。

MCP 的可选按需 Schema 模式只在 Run 已固定的工具集合内搜索；加载选择写入检查点并按 Run 隔离，工具执行仍经过原授权、审批、调用 ID 与 UNKNOWN 防重链路。搜索不授予连接或工具权限，不执行业务操作；同名工具继续使用原稳定标识。配置、换组和预算契约见 [工具搜索与按需 Schema](tools.md#mcp-工具搜索与按需-schema)。
