## 数据迁移与兼容

本批 F 不新增业务列或迁移；动态选择使用既有图检查点，预算中的加载数量为可选 JSON 字段。历史预算/Run 没有该字段时照常读取，默认静态模式保留既有工具暴露行为。

| 迁移 | 历史读取与回退边界 |
| --- | --- |
| 062：执行策略 | 旧审批布尔值保留并映射；活动的新策略运行阻止回退；允许回退时会移除来源/确认元数据，须理解信息损失。 |
| 063：鉴权与同步 | 兼容旧 Bearer；新鉴权、Headers 或范围撤销存在时阻止静默回退；允许回退时幂等操作回执会被移除。 |
| 064：连接共享 | 旧直接 Tool 关联继续可读；新连接关联、授权记录或 Run 来源存在时阻止有损回退。 |
| 065：审批与会话 | 旧 reject 保留原停止语义；新逐项决定、归属审计或待回收凭单存在时阻止有损回退。 |
| 066：预算与结果 | 旧预算/来源为空，不补造历史；已有结果来源时阻止有损回退，预算诊断本身可重算。 |

上述升级、回退、再升级、旧数据和模型一致性在临时 SQLite 中验证。本机开发 SQLite 业务库已于 2026-11-23 在备份及数据副本验证后由 061 升级至 066，Alembic 结构检查通过；升级前原有 54 张表的行数在迁移后、服务重启前保持一致。其他部署环境的升级，以及 MySQL/PostgreSQL 的隔离迁移与回退仍待对应环境验证。没有可据此承诺的跨数据库实测结论。升级命令和结构检查约定见 [测试与数据库](testing.md#数据库与测试)。
