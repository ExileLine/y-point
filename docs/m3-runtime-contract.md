# M3 Runtime 契约

## 所有权与身份

- `run_id` 标识一次提交和一次终态；重试必须创建新 Run 和新提交键，不能把失败 Run 改回排队。
- `thread_id` 标识跨轮检查点上下文，同一所有者可复用；同一线程同时只能有一个非终态 Run。业务库以可空且唯一的 `active_thread_id` 占用活动线程，创建 Run 时写入，进入终态时在状态事务中清空；并发提交冲突返回 409。
- `checkpoint_id` 是 LangGraph 已持久化状态的版本，不是公开游标。检查点只由 worker 访问，不向 API 或 SSE 返回。
- 运行使用提交时固定的模型、预算和工具开关；领取及工具调用仍须重新检查当前用户、模型和资源权限。

## 状态转换

| 当前状态 | 允许的后续状态 | 条件 |
| --- | --- | --- |
| `queued` | `running`, `cancelled`, `timed_out` | 原子领取且未过排队期限；所有者取消；排队期限到期 |
| `running` | `waiting_for_approval`, `completed`, `failed`, `cancel_requested`, `timed_out` | 保存审批及检查点；回答与完成同事务；受控故障；取消信号；执行时限 |
| `waiting_for_approval` | `running`, `cancelled`, `timed_out` | 已批准且检查点与动作摘要匹配；拒绝或取消；审批到期 |
| `cancel_requested` | `cancelled`, `failed`, `timed_out` | 执行器确认停止；租约过期或受控故障；执行超时 |

`completed`、`failed`、`cancelled`、`timed_out` 是终态。状态更新以版本号和租约条件原子执行，并在同一业务事务中追加状态事件。过期租约默认进入 `failed/lease_expired`，不自动重放模型或工具。只有可证明无工具、当前 Run 已结束的检查点允许补写最终回答。

执行器续租监视器无法确认租约时会立即取消正在执行的模型或工具任务。仍持有租约的 Run 记录脱敏的 `failed/lease_monitor_error`；若取消请求已提交，则确认 `cancelled`；租约已转移或状态已变化时，旧执行器只返回最新状态，不覆盖新持有者的结果。业务库持续不可用时无法提交终态，仍由后续租约到期回收处理。

## 数据与写入顺序

1. 创建事务同时写入 Run、用户 Message 与序号为 1 的 `queued` Event；提交后 worker 才能发现任务。
   同一所有者的 `request_key` 有唯一约束；并发提交撞上约束时，API 回滚并按提交键重新核对输入与配置，完全一致才返回已有 Run，否则返回 409。无匹配提交键的其他约束失败不会被当作幂等成功。
2. 领取事务写入租约、`running` 状态与事件。工具计数和 `tool_started` 同事务；工具结束单独写 `tool_completed` 或 `tool_failed`。取消或崩溃后允许只存在开始事件。
3. LangGraph Checkpoint 保存完整运行时状态；业务库只记录对应的 `checkpoint_id`。审批中断的检查点先持久化，再由业务事务写入审批摘要、检查点 ID 与 `waiting_for_approval` 状态。
4. 完成事务同时写入最终 assistant Message、`completed` 状态与事件。检查点和业务库不能跨库原子提交；若检查点已完成而业务事务未提交，仅在归属标记匹配、`tool_count=0`、图无待执行步骤且末尾为非空最终回答时补偿。
5. 检查点缺失、提前前进或审批摘要不匹配时停止继续执行，并记录脱敏 `checkpoint_mismatch`。若检查点归属同一会话已终结的失败 Run，且能证明该轮未调用工具或仅执行安全只读调用，下一轮可从最近确认点或首轮空起点分支，不重放失败轮次。Skill 文件读取与只读附件列表核对全部已计数开始事件，可保留 worker 中断后缺少结束事件的只读边界。用户 Tool 还须核对固定版本为 read、版本摘要一致、调用结束事件与审计状态和数量一致；未知结果、外部写入、缺失或矛盾审计均不放行。明确失败且该轮没有生成产物记录的 render_skill_document 可与这些只读调用一并放弃。检查点归属、所有者、Agent、会话、线程及时间顺序继续逐项核对，原 Run、事件与检查点保留，失败输入不自动带入新轮。

## 事件协议

- 协议版本当前为 `1`。`(run_id, sequence)` 唯一，Run 内序号从 1 单调递增；事件先入库，再由查询或 SSE 发布。
- `/events?after=N` 和 SSE `Last-Event-ID: <run_id>:<sequence>` 返回序号大于游标的事件。客户端按 `(run_id, sequence)` 去重；未知事件类型按相同游标推进并忽略其展示。
- `state`、`text_delta`、`reasoning_delta`、`tool_started`、`tool_completed`、`tool_failed`、`artifact_published` 是当前公开类型。事件只携带可见文本、脱敏故障码、工具名、服务端调用 ID 或已发布产物 ID；不携带工具参数、结果、凭据、隐藏推理或文件正文。
- `reasoning_delta` 仅保存供应商实际返回的公开思考文字或摘要，`disabled` 不发布；同正文共用租约、序号、授权和回放，不公开签名、密文或其他节点内容。会话消息的 `reasoning_content` 仅从这些公开事件恢复，不读取私有 Checkpoint；旧运行无记录时不补造。
- SSE 有积压时连续追平，空闲时每 200 毫秒查询并释放事务；心跳 10 秒、空闲关闭 60 秒使用单调时钟，不按轮询次数折算。前端动画只影响呈现，不能改变原始事件或最终 Message。
- 显式选择导出回答时，worker 在 Run 完成后另行发布 TXT 产物。发布事件可能晚于 `completed` 事件；SSE 在原有空闲窗口内等待产物发布，断线或窗口结束后客户端用原游标补取事件或查询产物列表。
- Message 是用户输入和最终可见回答；Event 是可回放的过程；Checkpoint 是私有恢复状态。Event 与 Message 的文字不应被当作检查点或重放工具的依据。

## 预算、取消与副作用

- 模型和工具调用在开始前按有效租约计数。Token 与估算成本在上游响应后累计，单次请求可能超额。排队期限只约束 `queued`，审批等待另用审批到期时间。
- 运行中取消先进入 `cancel_requested`，由 worker 取消协程后确认终态；阻塞的外部工具必须自行支持取消或受单次工具时限约束。若取消与超时终态竞争，执行器遇到版本冲突后有限次重读：已提交的取消请求优先被确认，已提交的超时终态不被后到取消改写；每次状态转换只追加一个连续序号的事件。
- Tool Registry 声明启用条件、读写属性、恢复策略和是否审批；执行器统一计数并记录脱敏事件。当前 `list_text_artifacts` 只返回本人小型 TXT 元数据，`read_text_artifact` 是只读、需审批的正文工具，两者每次执行都重新核对租约、用户、模型及供应商连接，读取还复核文件授权和哈希。
- 注册入口拒绝缺少审批或幂等/补偿声明的写工具；实际接入外部写工具前还必须实现幂等键、可验证补偿或人工核对流程，不能仅依赖声明。不得把检查点恢复视为外部写操作的重试许可。
- `RuntimeRunConfig` 固定本次 Run 的归属、线程、模型和工具名；`DeepAgentsRuntimeAdapter` 只负责图的创建、状态读取和事件流。平台执行器负责数据库事务、授权、取消、超时和恢复决策。

## 部署边界

`CHECKPOINT_BACKEND=sqlite` 保留私有文件检查点；`postgres` 使用独立 DSN 和 LangGraph 官方 PostgreSQL Checkpointer，业务数据库可以独立选择 SQLite、MySQL 或 PostgreSQL。worker 启动时初始化检查点表；全局检查点读取故障会阻止本轮过期租约回收，避免未完成补偿就判定 `lease_expired`。SQLite 与 PostgreSQL 检查点不会自动互迁，切换前须处理未完成 Run 和已有线程。隔离 PostgreSQL 验证已覆盖审批断线恢复及连续文本 Run；生产仍需验证账户最小权限、TLS、备份恢复、保留清理、真实模型长任务与多 worker 故障。生产数据库与对象存储的真实故障验收单独记录，不由本地测试代替。

## 检查点不一致核对与恢复

`checkpoint_mismatch` 是保护性终态，不允许把失败 Run 改回排队。若前述自动恢复条件不满足，先暂停该会话的新提交，保留业务库、检查点库和私有文件的同一时点备份；按用户、`session_id`、`thread_id` 和 Run 创建顺序核对最近完成 Run 的 `checkpoint_id`、当前检查点 ID、消息和事件序号。记录核对者、时间、差异及处置结果，不在日志或工单中复制检查点正文或凭据。

1. 检查点缺失：确认是否切换后端、数据库或恢复了不同时间点的备份。若原检查点仍可恢复，先在隔离副本验证线程归属与最后完成 Run 的 ID，再恢复服务。无法恢复时创建新会话；旧会话保持只读历史，不用可见消息伪造检查点。
2. 检查点比业务库前进：检查最新检查点的 `run_id` 归属、图是否终止、工具调用计数及工具事件。只有现有自动补偿条件全部成立时才由 worker 补写回答；有工具执行、待审批步骤或归属不明时，不重放模型或工具。核对外部副作用和生成文件后创建新会话继续。
3. 审批恢复不匹配：核对审批的检查点 ID、工具名、参数摘要、有效期及当前授权；过期或变化的审批不得沿用。由用户重新发起操作并获得新的审批。
4. 摘要失败：按上述归属及只读安全策略核对；可从最近确认的完成检查点或首轮空起点分支继续。涉及外部写入、未知执行结果、审计不完整或检查点归属不明时仍人工核对，不重放工具。

检查点保留以线程为单位，不能因为单个 Run 终态就删除线程：同一会话后续轮次、待审批 Run 与失败后的受限续聊都可能引用它。清理前须确认会话已删除或按明确策略永久归档、线程没有非终态 Run、业务消息与产物已按保留策略处理，且备份恢复窗口已结束；先在隔离副本验证恢复，再批量删除对应线程。当前没有自动线程清理作业，具体保留天数和备份删除边界由部署策略确定。


### 调用失败原因与会话总统计（2026-11-11）

`tool_failed` 可通过已有 `failure_code` 携带 `RunCallFailure` 的受控原因码，事件正文不保存工具输入、结果、异常原文或 stderr。正式工具中间件同时识别执行异常与 `ToolMessage.status=error`；成功与开始事件不允许设置失败码，未知原因码不能写入。调用摘要及消息内 `calls` 新增 `failure_code/failure_reason`，按固定映射生成中文说明，旧事件或未知历史码返回空码及明确的原因缺失提示；运行状态与单次调用状态继续独立。租约丢失后无法补造调用结束事件，原有 `interrupted` 语义保留。

`GET /api/v1/agents/{agent_id}/sessions/{session_id}/metrics` 每次复核会话所有者和 Agent 当前授权，并禁止缓存。按全部 Run 汇总，含失败、取消、排队和审批等待，提交至首次终态的累计耗时排除轮次间空闲、不叠加工具耗时；进行中累计到 `calculated_at`。返回 `run_count/active_run_count/elapsed_ms/total_tokens/missing_duration_runs/calculated_at`；未知历史时长单独计数，Token 只使用各轮上游累计已报告值。空会话耗时与用量为 0，非空且完全没有已报告用量时为 null。查询仅加载轻量计数器及终态时间，不读取正文、公开思考或私有检查点，也不受消息或 Run 列表分页影响。会话切换丢弃在途响应，活动时每 2.5 秒重新同步，累计耗时本地递增；界面保留已标记的临时错误快照，权限错误清空。


### 报告 Skill 选择纠正与安全续聊（2026-11-11）

`render_skill_document` 先核对 `RunSkill` 绑定再查询所选 Skill 的当前权限。未绑定的 ID 作为 `invalid_tool_arguments` 错误 ToolMessage 返回，包含 `/skill_id`、`retryable` 和仅限当前仍可访问固定模板的 `allowed_skills`；不查询该 ID 指向的外部资源，不自动猜选其他 Skill。模型可在同一 Run 的现有模型/工具/Token/时间预算内修正并交付真实模板产物。已绑定资源撤权、文件缺失及完整性失败不被转换为参数纠正。

`run_recovery.can_rewind_failed_run` 统一证明旧失败轮次可被安全放弃，结合公开调用、不可变版本摘要、只读 effect、审计状态/数量以及无生成产物记录；它不执行模型或工具、不修改历史。执行器只在已有归属及时间顺序条件同时成立时选用安全起点。即使此前多次提交均因 checkpoint_mismatch 结束，只要当前检查点仍归属原始安全失败，新的提问仍能从该起点分支。首轮失败恢复不携带失败输入，用户应重新发送待完成任务；历史耗时、Token 和失败记录保留。


### 历史与产物回读后超时的安全续聊（2026-11-12）

`read_file` 在正式事件中以原名出现时只代表当前会话虚拟历史回读，Skill 文件仍使用 `skill:名称@版本` 事件。历史回读与 `read_generated_artifact` 都属于平台只读路径；恢复规则必须同时覆盖这两类调用，成功和明确失败均可安全放弃，但须有完整、同名、唯一关联的开始/结束事件，并与该轮工具计数一致。名称近似、未知/未绑定工具、写工具和缺失结束事件均不适用；用户 Tool 继续要求固定只读版本与完整一致的审计，不扩大外部写入边界。

产物读取收到不可用 ID 时已返回可纠正错误 ToolMessage；若后续模型请求又发生上游读取超时，原 Run 保留 `timed_out/provider_timeout` 和工具失败事件。新 Run 可从最近成功检查点分支，保留成功轮次上下文及产物，不继承失败轮次输入、待执行工具或内部纠正消息。即使中间已有多个 `checkpoint_mismatch` 失败，新提交仍追溯当前检查点所属的真实失败轮次；连续两轮新提问都应可完成。该恢复只选择检查点，不修改原 Run 或检查点，也不重放工具。


### 输出空额度的生成预留与未完成内容展示（2026-11-12）

Agent 的 `max_output_tokens=null` 继续表示 SDK 请求不发送固定最大输出 Token；这不表示生成不需要占用上下文。登记窗口时，平台为这种配置预留窗口的四分之一，扣除固定开销后计算输入预算，摘要触发阈值仍为输入预算的 75%。完整模型请求的消息、系统指令和获准工具契约也受该预算约束。显式整数额度继续使用原有 SDK 输出预留规则；未知窗口沿用既有行为。预留只是输入规划，不覆盖供应商默认额度、真实输出上限或实际分词；明确的 length/max_tokens 截断仍记录 `model_output_limit_exceeded`，禁止执行被截断的工具参数，不通过自动放宽额度或重放工具掩盖错误。

会话历史接口为每个已授权消息增加 `partial_content/run_state/failure_code`。仅失败、超时或取消轮次的已公开 `text_delta` 按序合并为部分正文；成功和进行中返回空部分正文，成功回答仍取完成事务的助手消息。它是展示元数据，不新增助手消息，不修改终态、检查点、用量、产物发布或后续模型输入。思考继续走独立字段，关闭思考时不展示；工具参数、原始结果、内部摘要及未公开文本不属于部分正文来源。历史接口照常检查用户、Agent、会话和消息游标。

页面在流式转失败时继续保留缓冲正文、停止输出光标并标记未完成；历史请求延迟时也不能清空。刷新后从上述字段恢复正文，失败原因可键盘展开，复制仅复制正文。下一轮与旧轮独立展示，不重复追加成功消息。既有未公开正文无法追补，公开事件仍在的历史无需数据迁移即可恢复展示。
