# M6.4 删除故障收口记录

日期：2026-11-13。修复模型失效时知识文档删除被回滚的问题，不将真实业务质量或目标部署验收标记为完成。

## 根因与行为

最小复现命令：`.venv/bin/python -m pytest tests/test_knowledge_deletion.py -q --disable-warnings --tb=short`。修改前停用加工模型会得到 HTTP 409/10005「文档加工模型未通过文本验证或当前不可用」，测试在删除应成功的断言处失败。

删除调用索引调度，调度重新验证模型，校验错误使同一事务中的逻辑删除回滚。修复后拆分版本推进、配置准备与任务保存；删除成功不依赖模型有效性。有效配置仍自动创建完整代；已失效配置返回成功删除、可空 job_id 和明确人工重建原因，不保存不完整模型身份，也不放宽正常上传与重建。

删除同时请求取消旧任务和受影响 Run，旧任务阶段与发布检查核对 revision。所有历史版本的引用、预览和 PDF 原页按当前文档删除状态拒绝访问。无剩余文档且配置失效时清空活动指针，空库直接无答案；仍有文档时保留旧索引，混合检索模型失效仍需修复，不静默降级。后台清理流程继续移除 Blob、原文和全文/向量片段。

版本冲突、越权和其他服务异常继续作为失败回滚，页面保留文档及错误。成功删除但重建暂缓时，页面显示独立警告、模型原因和检查设置入口，不声称已有新任务。

## 页面人工复测

1. 建立一次性测试知识库，配置专用加工/嵌入模型，上传两份带不同检索词的文件，等待索引完成并保留引用。
2. 停用测试模型或其供应商，删除其中一份文件。删除应成功、目录移除该文件，并提示重建暂缓及原因；旧引用、加工预览和 PDF 原页应不可访问。
3. 对剩余文件使用明确的关键词检索核对内容；失效的向量模型修复前，混合检索不保证可用。
4. 删除最后一份文件，确认空库检索无答案。恢复模型并在设置保存重建，新索引应不包含已删除文档。
5. 使用旧 revision 提交删除仍应返回 409，其他用户无管理权限仍返回 404；失败时页面应保留文档。

本轮不操作开发业务库、不请求收费模型，无数据库迁移。API 本机开发启动器启用 reload；worker 发布校验与清理逻辑未改动。真实业务文件、供应商解释质量/实际费用、PostgreSQL/MySQL/S3/Docker 及容量验收继续保留。
